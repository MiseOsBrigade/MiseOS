# Mise-en-Preplist Brand Kit

Mise-en-Preplist is a prep-kitchen themed GitHub bootstrap system. It helps users stage a small repository, run one safe workflow, unzip a prepared project payload, test it, and commit the expanded repo in the right order.

---

## Brand Position

**One-line description**

> A prep-kitchen workflow for self-unzipping GitHub starter repositories.

**Short description**

> Mise-en-Preplist turns a compressed project payload into a clean, ordered GitHub repository using a safe unzip script, GitHub Actions, and a step-by-step README.

**Long description**

> Mise-en-Preplist is a GitHub bootstrap template built for clean project handoff. The repository starts small: a README, workflow, safe unzip script, and payload archive. After the first push, the operator runs the Bootstrap Unzip workflow. The workflow validates the archive, extracts the project files, installs dependencies when needed, runs tests when available, writes a bootstrap marker, and commits the expanded repository back to the branch.

---

## Voice

Use language that feels like a calm prep cook and a precise release engineer working the same station.

**Voice rules**

- Clear before clever.
- Operational, not hype-heavy.
- Culinary metaphors should explain the workflow, not hide the technical facts.
- Use verbs that imply order: prep, stage, verify, fire, plate, serve.
- Keep safety language direct: validate the payload, block unsafe paths, commit only after checks.

**Good phrases**

- Prep the payload.
- Fire the workflow.
- Plate the expanded repo.
- Keep the line clean.
- Verify before service.
- Safe unzip, clean commit.

**Avoid**

- Magic automation.
- Self-executing README.
- Fully autonomous without explanation.
- Claims that GitHub runs code from README content.

## Asset Usage Notes

- Keep the logo on high-contrast backgrounds.
- Use the mark when the full name would be too small to read.
- Use the banner at the top of the README.
- Use `social-preview.svg` in GitHub repo settings under **Social preview** after exporting it to PNG if GitHub requires upload compatibility.
- Do not describe the README as executing code. The workflow executes the bootstrap after the README and workflow are deployed.
