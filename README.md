## Registry

MiseOS models software delivery as a coordinated roster of character agents. Each character has a clickable identity, dedicated profile, machine-readable metadata, operational workflow, and proof gate. Character identity and personality describe behavior; runtime permissions independently determine authority.

> No merge, deployment, publication, billing action, or mint without evidence.

## Runtime trust model

MiseOS defaults agents to least privilege and read-only operation. Shell, repository write, network, deployment, publication, billing, minting, and merge capabilities require explicit policy authorization. Privileged execution must produce auditable evidence and remain subject to human or independent policy approval where configured.

## Repository structure

- `characters/<slug>/README.md` — individual character profile
- `characters/<slug>/metadata.json` — executable registry metadata
- `assets/characters/<slug>/profile.svg` — clickable identity tile
- `data/characters.json` — 112-character index
- `data/miseos-ecosystem-135.json` — 112 characters + 23 registry manifests
- `packages/*` — schema, catalog, and profile utilities
- `.github/workflows/*` — registry validation, integrity, dependency review, and CodeQL
