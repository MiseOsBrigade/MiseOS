# MiseOS Brand & Marketing Strategy

## Positioning

MiseOS is the kitchen operating system for autonomous development. Everything in its place before it ships.

## Official Ecosystem Language

> **112 character agents + 23 registry manifests = 135 MiseOS ecosystem items.**

The two layers serve different purposes:

- **112 character agents** — collectible brigade operators with roles, departments, rarity, lore, workflows, and bounded permissions.
- **23 registry manifests** — product infrastructure including SDKs, packages, containers, schemas, policies, analytics, workflow packs, templates, themes, and system tools.

Do not describe the ecosystem as `135 characters`, `135 character cards`, or `135 autonomous agents`.

## Core Positioning

**MiseOS is the kitchen operating system for autonomous development.**  
**Everything in its place before it ships.**

MiseOS turns AI chaos into coordinated service: a Git-native DevOps operating system where specialized agents build, test, secure, deploy, observe, and document software through repo-safe workflows.

## Core Audience

- Indie builders who need repo-safe automation.
- DevOps teams that need safer AI workflows.
- Open-source maintainers who need triage, releases, docs, and policy checks.
- Teams experimenting with MCP, GitHub Apps, and agentic CI/CD.
- Organizations that need evidence, bounded permissions, and human approval around AI operations.

## Product Story

Every software team is a kitchen. Commits are ingredients. Pull requests are tickets. Releases are service. MiseOS gives every agent a station, every workflow a recipe, and every release an evidence trail.

The character brigade makes the system understandable and memorable. The registry catalog makes the system installable, distributable, licensable, and commercially useful.

## Marketplace Copy Rules

Registry manifests must be described as developer tools or product infrastructure.

Preferred terms:

- SDK
- package
- container
- policy tool
- schema
- workflow pack
- analytics engine
- system agent
- template
- theme
- Marketplace action

Avoid collectible-card language for registry products. Do not assign rarity, lore, character roles, brigade identity, or card numbering to a registry manifest unless a separate licensed collectible edition is intentionally created.

### Marketplace Example

**MiseOS Repo Reliability Kit** is a reusable workflow package that adds repository validation, dependency checks, release evidence, and policy gates to GitHub-based projects.

## NFT and Card Language

The NFT/card collection is a brand and community layer, not a dependency of the core SaaS runtime.

Use:

```text
112 character cards
23 registry manifest badges
135 total ecosystem items
```

Character items may use terms such as collectible, agent card, rarity, lore, edition, attributes, and abilities.

Registry items should use terms such as manifest badge, product badge, package badge, infrastructure badge, compatibility, version, distribution, and license.
