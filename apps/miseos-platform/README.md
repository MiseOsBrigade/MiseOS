## 🚀 What Is MiseOS?

MiseOS is a Git-native coordination layer inspired by *mise en place*: everything in its place before service begins.

- **🃏 Character agents:** specialists represented as collectible trading cards with roles, rarity, lore, stats, permissions, and proof gates.
- **🧱 GridOps:** a multidimensional repository playground for visualizing work, agents, evidence, incidents, packages, and release state.
- **🛡️ Trust-native automation:** bounded actions, human approvals, evidence requirements, and ethical checks.
- **📦 Product registry:** SDKs, packages, containers, schemas, policy tools, workflows, analytics, and themes.
- **💳 Commercial readiness:** open-core product tiers with provider-neutral billing configuration and no secrets committed to Git.

**Think of it as:** a digital kitchen brigade walking through your repository before service—checking prep, cleaning stations, routing orders, protecting secrets, and proving the system can serve.

## ⚡ Quick Start

### Run the current GridOps proof

```bash
python3 -m http.server 8080
```

Open `http://localhost:8080`.

- [`index.html`](index.html) — GridOps command playground
- [`characters.html`](characters.html) — interactive character demonstration roster
- [`README_3D_CHARACTER_CAROUSEL.md`](README_3D_CHARACTER_CAROUSEL.md) — GitHub-native gallery layout and asset-path contract for the 75 repository-backed characters
- [`REGISTRY_CARD_GALLERY.md`](REGISTRY_CARD_GALLERY.md) — card art gallery for registry manifest products (SDKs, packages, containers, agents)
- [`output/manifests/REGISTRY_CATALOG.md`](output/manifests/REGISTRY_CATALOG.md) — canonical package registry

### Generate roster and registry outputs

```bash
python3 scripts/validate_repository.py
```

The local backend prepares manifests before any paid image generation is attempted.

### Validate before proposing a merge

```bash
python3 scripts/validate_repository.py
```

## 🃏 Trading Card Schema

Every character is usable as both an operational agent and a collectible card.

```json
{
  "token_id": 1,
  "name": "Mise Garde",
  "division": "RepoOps",
  "class": "Pull Request Guardian",
  "rarity": "Rare",
  "specialty": "PR hygiene and merge readiness",
  "signature_move": "Clean Diff Sweep",
  "proof_gate": "No merge without visible checks",
  "stats": {
    "review": 92,
    "security": 84,
    "speed": 76,
    "reliability": 95
  },
  "media": {
    "image": "ipfs://REPLACE_AFTER_UPLOAD",
    "animation_url": "ipfs://REPLACE_AFTER_UPLOAD",
    "model_3d": "ipfs://REPLACE_AFTER_UPLOAD",
    "audio": "ipfs://REPLACE_AFTER_UPLOAD",
    "ar": "ipfs://REPLACE_AFTER_UPLOAD"
  }
}
```

No placeholder URI should be minted or advertised as live.

## 🛡️ Safety Boundaries

See [`CONTRIBUTING.md`](CONTRIBUTING.md) and [`SECURITY.md`](SECURITY.md).

- force-pushing protected branches;
- printing raw secret values;
- disabling CI to manufacture a green result;
- rewriting history without explicit approval;
- changing production deployment or billing settings without approval;
- minting placeholder metadata;
- merging when required validation is unknown.

---

## 🤝 Contributing

1. Create or update one clearly owned system.
2. Include a working local proof.
3. Add tests or validation evidence.
4. Document permissions, secrets, cost, and rollback boundaries.
5. Open a pull request; do not merge unknown validation.

Recommended character structure:

```text
agents/<division>/<character>.md
metadata/<token_id>-<character>.json
cards/<token_id>-<character>.md
media/{images,animations,models,audio,ar}/
```
